# Guia do Aluno — Mutirão

> **A escrever na Fase 3.5**, depois que a interface estiver estável e antes de
> qualquer turma entrar. Precisa de captura de tela em toda etapa que envolve clicar.
>
> Estrutura obrigatória definida em [`plan.md`](plan.md), seção 15.3.
> O exemplo completo ponta a ponta está na seção 15.5 e deve ser percorrido
> de verdade, usando o próprio Mutirão como cobaia.

## Estrutura obrigatória

1. Antes de começar — conta no GitHub, acesso, ambiente
2. Entender o quadro — backlog, sprint, cada status
3. Pegar uma demanda — como escolher, o que perguntar antes de assumir
4. Estimar — o que é ponto, como funciona em grupo
5. Desenvolver — fork, branch, commits
6. Abrir a PR — título, descrição, o que anexar
7. Passar pelo review — como receber e responder crítica
8. Entregar — merge, homologação, demo
9. **Quando dá errado** — atrasei, travei, não entendi, conflito, PR não vinculou

## O item 9 é o mais importante

Quase todo aluno que some do projeto some porque travou e não sabia que podia
avisar. Registrar impedimento precisa aparecer como comportamento normal e
esperado, nunca como confissão de fracasso.

## Enquanto este guia não existe

A hora de escrever cada trecho é **quando alguém faz a pergunta pela primeira vez**.
Aluno perguntou como resolver conflito de merge? A resposta vem para cá antes de
ir para o aluno.
